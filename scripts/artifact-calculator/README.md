# 유니온 아티팩트 배치 계산기

`Run-ArtifactCalculator.cmd`를 더블클릭하고 **현재 아티팩트 레벨(1~60)**을 입력한다. 총 AP와 해금된 크리스탈 수를 자동 계산해 최적 배치를 표시한다. 결과를 본 뒤 다음 레벨을 입력하면 된다. 빈 입력은 직전 레벨 재사용, `q`는 종료다.

현재 배치를 유지하며 남은 AP만 쓰는 계산이 아니라 **해당 레벨의 총 AP로 전체 배치를 다시 계산**한다. 게임 내 초기화·옵션 변경을 실행하지 않으며, 실제 효과가 유지되려면 크리스탈이 활성 상태여야 한다.

## 계산 기준

아래 순서를 엄격히 적용한다. 뒤의 기준 때문에 앞의 최적값이 줄어들지 않는다.

1. 치확 **적용 Lv.10 필수**. 원시 합계가 10을 초과하는 배치도 허용한다.
2. 핵심 6종인 **치확·크뎀·공마·보공·데미지·방무의 적용 레벨 합계 최대화**.
3. 핵심 합계가 같으면 `크뎀 → 공마 → 보공 → 데미지 → 방무` 순으로 최대화한다.
4. 앞서 확정한 핵심 효과를 유지하면서 **전체 12종의 적용 레벨 합계 최대화**.
5. 전체 합계도 같으면 `올스탯 → 드롭 → 메획 → 경험치 → 벞지 → 재사용` 순으로 최대화한다.
6. 효과도 모두 같으면 **사용 AP 최소화**. 완전 동점이면 배치 하나를 출력하며, 크리스탈 행별 배치는 실행마다 달라질 수 있다.

핵심 6종 모두 Lv.10이 가능하면 반드시 확보한다. 불가능하면 치확 10을 유지하며 핵심 합계부터 최대화한다. **핵심 효과를 위해 전체 합계가 줄어드는 것은 허용하며 손실 상한은 없다. 올스탯을 위해 확정된 전체 합계를 줄이지는 않는다.** 핵심 합계가 같은 경우에도 핵심 효과별 우선순위가 전체 합계보다 앞선다.

주황버섯의 **치확/크뎀/공마**, 뿔버섯의 **보공/데미지/방무** 옵션을 고정한다. 두 크리스탈의 레벨은 변경 가능하다. 나머지 크리스탈의 옵션·레벨은 자유롭게 계산한다. 치확 외에 최소 레벨을 강제하지 않고, 우선순위에 따라 가능한 최댓값을 찾는다.

최종 목표는 12종 각각 Lv.10, 실제 효과 레벨 총합 **120**이다. 최대 HP/MP·상태이상 내성·소환수 지속시간·파이널 어택은 대상에 포함하지 않는다. **최적해는 이 우선순위에 대한 최적 배치이며 실제 보스 피해량 최대화를 뜻하지 않는다.** 피해량·직업별 효율·옵션 변경 비용·장기 성장 순서는 계산하지 않는다. AP와 옵션 변경 등에 사용하는 아티팩트 포인트는 별개다.

## 입력과 출력

- 레벨 `L`의 총 AP: `L + floor(L / 5)`.
- 크리스탈 수: `3 + floor(L / 10)`.
- 각 크리스탈은 Lv.1~5, 서로 다른 옵션 3개. 누적 AP 비용은 `0 / 1 / 3 / 5 / 8`.
- 같은 효과의 원시 합계는 해당 크리스탈들의 레벨 합, 적용 레벨은 `min(원시 합계, 10)`이다.
- `실제 효과 합 = 3 × 크리스탈 레벨 합 − 전체 초과분 합`으로 검산한다.

결과에는 레벨·총 AP·크리스탈 수, 크리스탈별 레벨/옵션/AP, 남은 AP, 크리스탈 레벨 합, 핵심 6종 효과 합계(`/60`), 올스탯 적용 레벨(`/10`), 실제 효과 레벨 총합(`/120`), 12종 전체의 원시/적용/초과분, 계산 시간을 표시한다. 6번째 이후 크리스탈은 번호로 표시한다. 결과 파일은 자동 저장하지 않는다.

명령행으로 한 번만 실행할 수도 있다. 먼저 이 폴더로 이동한다.

```powershell
.\.venv\Scripts\python.exe .\calculator.py --level 20
```

일반 사용자는 레벨만 입력한다. AP와 크리스탈 수를 직접 받는 `solve(budget, count)`는 내부 검증용이다. `Ctrl+C`는 계산을 중단하고 반복 입력으로 돌아간다. 입력 대기 중 `Ctrl+C` 또는 입력 종료(EOF)는 프로그램을 종료한다.

종료 코드는 단발 실행 기준으로 성공 `0`, 계산 오류 `1`, 조건 충족 불가능/잘못된 인자 `2`, 계산 중단·미완료 `130`이다. 반복 실행은 각 결과를 안내하고 다음 입력을 받는다. 계산이 끝나지 않은 해를 최적해나 불가능으로 표시하지 않는다.

## 정확성과 구현

Python 3.12와 OR-Tools CP-SAT을 사용한다. **핵심 합계 → 핵심 효과 5종 → 전체 합계 → 나머지 효과 6종 → AP 최소화**의 14단계 정수 최적화를 수행한다. 각 단계가 `OPTIMAL`인 경우에만 값을 고정하고 다음 단계로 넘어가며, 앞 단계 해를 다음 단계의 탐색 힌트로 재사용한다.

`core_total == sum(effective[:6])`으로 핵심 합계를 표현한다. `model.maximize(...)`로 목표를 최대화하고, 구한 값을 `model.add(objective == optimum)`으로 고정한다. 전체 합계는 7번째 단계에서 최대화하므로 핵심 효과를 낮춰 다른 효과를 늘릴 수 없다. 기존의 올스탯 확보 여부(0/1) 변수는 사용하지 않는다.

`Metrics.objective_values`는 실제 배치에서 다시 계산한 단계별 값을 제공한다. 최적화 엔진이 확정한 값과 모두 일치해야 정상 결과로 반환한다. `Metrics.rank`는 같은 순서로 비교하되 마지막 AP만 음수로 바꿔, 효과가 같으면 적은 AP를 선호한다.

자유 크리스탈은 같은 레벨끼리 묶는다. 레벨별 개수가 `c`일 때 효과별 배치 개수를 `0~c`로 제한하고 전체 옵션 수를 `3c`로 맞춘다. 이 조건은 각 크리스탈에 서로 다른 옵션 3개를 배치하는 것과 동등하다. 남은 배치 개수가 가장 큰 효과 3개씩 선택해 실제 크리스탈로 복원하며, 복원 뒤 별도 검산 함수로 모든 조건을 다시 확인한다. 크리스탈 자리만 바꾼 중복 탐색을 없애기 위한 표현이며 근사 계산이 아니다.

가능한 레벨 조합과 치확 초과분으로 총합의 안전한 상한을 계산한다. 개별 효과 최적값이 확정될 때 해당 레벨을 만들 수 없는 조합을 제외하고, 전체 합계의 상한을 이용한 제외는 7번째 단계에서 전체 합계를 확정할 때 적용한다. 핵심 합계 단계에 전체 합계용 가지치기를 적용하지 않는다. 크리스탈 레벨 합 자체를 우선 최적화하지 않는다.

코드는 다음 책임으로 나뉜다.

- `artifact_engine.py`: 모델 생성(`_build_model`), 목적함수 순서(`_build_objectives`), 단계별 최적화(`_optimize`), 배치 복원(`_extract_crystals`), 독립 검산(`verify`). `solve`가 전체 흐름을 연결한다.
- `artifact_output.py`: 한글 표와 결과 출력.
- `calculator.py`: 명령행 인자, 반복 입력, 실행·오류·중단 처리.
- `test_calculator.py`: 전수 탐색 대조 및 실행 경로 검증.

효과 교환 후보 비교 기능과 전용 모듈·테스트는 제거된 상태다. `c`, `--compare`, `--loss`, `--candidate`는 지원하지 않는다. 별도의 6종/7종 모드 없이 위 정책을 기본으로 사용한다.

## 실행 환경과 재설치

이 PC에는 전용 `.venv` 설치를 완료했다. 이후 실행에는 네트워크나 NEXON API key가 필요 없다. `.venv`는 Git에 포함하지 않는다.

현재 가상환경은 Codex가 제공한 Python 3.12.14를 기반으로 한다. 해당 런타임이 삭제·이동되면 설치된 다른 Python 3.12를 지정해 환경을 다시 준비해야 한다. 실행기는 PATH의 `python`/`pwsh` 별칭 대신 이 폴더의 가상환경을 직접 호출한다.

다음 명령은 **이 폴더에서** 실행한다. 다른 PC에서는 첫 줄을 실제 Python 3.12 실행 파일 경로로 바꾼다. 전역 Python 패키지는 변경하지 않는다.

```powershell
$artifactPython = Join-Path $env:USERPROFILE '.cache\codex-runtimes\codex-primary-runtime\dependencies\python\python.exe'
& $artifactPython -m venv --without-pip .venv
New-Item -ItemType Directory -Force .venv\tmp | Out-Null
$artifactOldTemp = $env:TEMP
$artifactOldTmp = $env:TMP
try {
    $env:TEMP = (Resolve-Path .venv\tmp).Path
    $env:TMP = $env:TEMP
    & .\.venv\Scripts\python.exe -m ensurepip --upgrade --default-pip
    if ($LASTEXITCODE -ne 0) { throw 'pip 준비 실패' }
    & .\.venv\Scripts\python.exe -m pip install --no-cache-dir -r requirements.txt
    if ($LASTEXITCODE -ne 0) { throw '패키지 설치 실패' }
} finally {
    $env:TEMP = $artifactOldTemp
    $env:TMP = $artifactOldTmp
}
```

## 검증 결과

2026-10-15 KST, Python 3.12.14 / OR-Tools 9.15.6755에서 자동 테스트 **21개가 모두 통과**했다(32.551초). 아래 표는 새 정책의 실제 검증 결과다.

```powershell
.\.venv\Scripts\python.exe -m unittest -v
```

- 3개 크리스탈의 27,500개 레벨·옵션 배치를 전수 탐색하여 AP 0~24의 최적 순위를 비교한다. 정답 계산은 엔진의 순위·가지치기·검산 함수를 사용하지 않는다.
- Lv.1~60 전체의 반환 배치를 검산하고, 가능·불가능 판정을 별도의 레벨 조합 열거로 대조한다. 이는 전체 규모의 모든 배치를 독립 전수 탐색한 것은 아니다.
- 통제된 후보로 핵심 합계·핵심 개별 효과·전체 합계·나머지 효과·AP 순서를 검증한다. 이 후보는 정책 검사 전용이며 게임에서 가능한 배치라는 주장은 하지 않는다.
- 원시 합계 초과분 제외, 그룹 복원, 오류와 중단 구분, 반복 입력, 한글 출력, 제거한 명령 거부, 다른 작업 폴더의 `.cmd` 실행을 검사한다.

대표 레벨의 별도 측정 시간은 Lv.20 **0.266초**, Lv.25 **0.314초**, Lv.30 **0.465초**, Lv.60 **0.949초**였다. 동일 PC에서의 단일 측정이며 실행마다 달라질 수 있다.

Lv.20·21은 `치확10 / 크뎀10 / 공마10 / 보공9 / 데미지9 / 방무9`, 그 외 0이다. Lv.30은 핵심 6종과 올스탯 각각 10, 드롭 5, 그 외 0이다. Lv.60은 전체 12종이 각각 10이며, AP58로는 전체 120을 달성하지 못함을 확인했다.

Lv.25는 이전 총합 우선 정책의 전체 63 대신 핵심 6종 각각 10인 전체 60을 선택한다. 같은 효과를 유지하는 배치 중 AP를 최소화하므로 AP27을 사용하고 3을 남긴다. 남은 AP를 모두 쓰는 것이 목표는 아니다. 이전 정책의 Lv.21 총합58, Lv.23 방무8·올스탯2 예시는 현재 최적 출력에 해당하지 않는다.

Windows 탐색기의 실제 마우스 더블클릭과 게임 내 적용은 확인하지 않았다. 더블클릭이 호출하는 `.cmd`를 별도 작업 폴더에서 실행하는 경로는 자동 테스트로 확인했다.
