## C08 — CloudFront Real-time을 Standard의 완전한 상위호환으로 보지 않음

**문제**

Real-time Logs가 수초 단위라는 이유만으로 Standard보다 모든 면에서 우월하다고 오해할 수 있었다.

**승인 교정**

둘은 동일 목적의 완전한 대체 관계가 아니다.

| 관점 | Standard Logging v2 | Real-time Access Logging |
|---|---|---|
| 지연 | 일반적으로 1시간 이내, 일부 최대 24시간 | 수초 내 Kinesis 전달 |
| 주 목적 | Archive, Historical analysis, Audit | 저지연 Monitoring·Alert |
| Destination | CWL, Firehose, S3 | Kinesis Data Streams |
| Sampling | Real-time의 핵심 기능과 다름 | 1~100% 설정 가능 |
| 비용 | Destination ingest/storage | CloudFront Real-time + Kinesis |
| 운영 | 비교적 단순 | Capacity·Consumer·Throttle 필요 |
| 완전성 | Best-effort | Best-effort + Sampling 가능 |

같은 Viewer Request 활동을 관찰해도 동일 Record 집합을 일대일로 제공한다고 가정하지 않는다.

**적용 대상**

- `../Telemetry와 로그 지연 모델.md`

**검증 Anchor**

- `CloudFront Standard와 Real-time은 완전한 상위·하위 관계인가?`
- `동일한 Record 집합을 일대일로 제공한다는 뜻은 아니다`
