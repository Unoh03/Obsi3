# 시연 장면별 근거 파일

> [!IMPORTANT] 문서 목적
> [[시연 대본]]의 SC-00부터 SC-09까지 각 장면을 뒷받침하는 계획, 구현, 설정,
> 정적 검증 파일을 한곳에서 찾기 위한 근거 색인이다. 이 문서는 코드 설명을 대신하는
> 보고서가 아니라, 발표 문장에 의문이 생겼을 때 어떤 원본을 열어야 하는지 알려주는
> 탐색 지도다.

## 1. 근거 등급

| 등급 | 의미 | 단독으로 주장할 수 있는 범위 |
|---|---|---|
| `계획·계약` | 목표 흐름, 장면 순서, 중단 조건 | 의도와 검증 기준 |
| `구현·설정` | 실제 Source, IaC, Rule, Workflow | 구조와 동작 방식 |
| `정적 검증` | Test가 검사하는 계약 | Source가 고정 계약을 만족함 |
| `Runtime 증거` | Alert, Execution, Run, Commit, Argo Revision, 실제 결과 | 해당 TAKE에서 실제로 일어난 결과 |
| `공백·잠금` | 구현 또는 Runtime 검증이 부족함 | 성공 주장 불가 |

저장소 파일은 구현과 검증 계약을 증명하지만, 이번 촬영에서 실제로 성공했다는 사실까지
대신하지는 않는다. Runtime 주장은 같은 TAKE의 식별자와 화면을 별도로 남겨야 한다.

## 14. Runtime 증거 연결표

최종 TAKE에서는 다음 식별자를 한 묶음으로 기록한다.

| 구간 | 식별자 또는 파일 |
|---|---|
| Health | Rule 100102 Alert ID, `<take_id>-source.json` |
| 공격 실행 | `capital-one-baseline.json`, TAKE ID, 시작 UTC |
| 조기탐지 | Rule 100110 Alert ID, Source Event ID |
| 격리 | Shuffle Execution ID, GitHub Run ID, `soc-containment-result.json` |
| 격리 배포 | Commit SHA, Argo Revision, Pod name·UID |
| 침해확정 | CloudTrail eventID, Rule 100111 Alert ID |
| Hardening | Shuffle Execution ID, GitHub Run ID, `soc-hardening-result.json` |
| Hardening 배포 | Commit SHA, Argo Revision, 새 Session impossible |
| WAF | WAF Rule ID, Apply 시각, Runtime Read-back |
| 재공격 | REATTACK_ID, CloudFront Request ID, `capital-one-waf-reattack.json` |

서로 다른 TAKE의 식별자를 한 사건처럼 이어 붙이지 않는다.
