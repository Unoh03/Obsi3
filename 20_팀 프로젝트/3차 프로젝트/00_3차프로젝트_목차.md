# 3차 프로젝트 목차

## 현재 진행·판단

- 최신 정리: [[20_팀 프로젝트/3차 프로젝트/일일 로그/2026-07-28_일일_로그|2026-07-28 일일 로그]]
- 학원 3차이자 마지막 프로젝트는 `2026-07-28`에 시작했다.
- 첫날에는 공격 기법을 먼저 확정하던 접근을 보정하고, `실제 사고 사례 → 보호할 서비스와 인프라 → 공격·장애 검증 → 로그·조치·재점검` 순서로 방향을 다시 잡았다.
- 기존 2차 인프라의 재활용, Terraform 재구성, 완전 자동 CI/CD 포함은 현재 공유된 방향이다.
- 재현할 사고 사례, 최종 서비스 기능, Terraform 재사용 범위, CI/CD 구현 방식과 팀 역할은 아직 확정되지 않았다.
- 현재 최종 팀 계획서는 없다. 상담 전 개인안과 후보 평가는 현재 팀 계획으로 간주하지 않는다.

## 현재 재시작 지점

- 병렬 확인: 실제 Cloud·Container 보안 사고 사례 후보를 `원인 설정 → 진입점 → 권한·데이터 흐름 → 피해 → 탐지·조치` 기준으로 비교한다.
- 병렬 확인: 기존 2차 Architecture에서 재사용할 Resource와 보호할 서비스·사용자·데이터·정상 요청 흐름을 확인한다.
- 결정 지점: 사고 사례와 기존 기반이 자연스럽게 만나는 교집합에서 현재 팀 계획을 확정한다.
- 후속 결정: 현재안이 확정된 뒤 Terraform·CI/CD·보안 검증 범위를 구체화한다.

## 기록 경계

- 강사 원문, 팀 결정, 실제 실행 결과와 AI 해석을 구분한다.
- 팀 전체 성과와 개인 기여를 별도로 기록한다.
- 개인 계획서와 후보 평가는 팀의 최종 결정으로 간주하지 않는다.
- Access Key, Token, 비밀번호, kubeconfig 등 Secret은 Vault에 기록하지 않는다.
- AWS 생성·변경·삭제와 비용 검증은 실제 계정·명령 출력으로 확인한다.
