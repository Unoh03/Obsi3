# 8.19 멘토님과 상담

> [!IMPORTANT] 최신 판정의 시작점
> 이 파일은 상담 원메모와 후속 연구를 연결하는 **인덱스**다.  
> 상담 중 작성한 원문과 당시의 `UNRESOLVED` 가설은 `[[8.19 멘토님과 상담 - 원본 기록 (SUPERSEDED)]]`에 그대로 보존했다. 원본 기록에는 음성인식 오류·불완전한 답변·나중에 폐기된 잠정 해석이 포함돼 있으므로, 외부 발표·보고서의 직접 근거로 사용하지 않는다.  
> 원본 보존본은 당시 기록을 훼손하지 않기 위해 본문을 재작성하지 않았고, 파일명 `(SUPERSEDED)`와 이 인덱스의 경고로 최신 정본과 강하게 분리한다.

## 현재 Runtime 체크포인트

| Gate | 현재 판정 | 의미 |
|---|---|---|
| G0~G2 | PASS | Workflow·인증·합성 Payload 왕복 및 wrong/missing Header 거절 검증 |
| G3 | strict Runtime PASS | Wazuh Integrator·Rule·Sanitizer·Runtime 설정 검증 |
| G4 | **미완료** | 실제 Rule `100103` Alert ↔ Shuffle Execution 일대일 Runtime Evidence가 아직 없음 |

따라서 현재는 다음 문장을 사용하지 않는다.

```text
실제 Wazuh Alert → Shuffle Execution E2E 완료
자동 대응 완료
```

G4가 완료된 뒤 Evidence 경로·SHA-256과 함께 승격한다.

## 최종 설계 해석

```text
하나의 Incident Detection/Response 흐름
├─ Source별 특성에 맞는 Telemetry mechanism
├─ 가능한 범위의 Event-driven 전달
├─ Wazuh 중앙 분석·탐지
├─ 초기 고신뢰 신호 → 제한적·가역적 Containment
├─ 추가 Evidence → 범위·영향·확신도 보강
└─ Archive/Poll → 보존·Replay·누락 보완·과거 조사
```

`빠른 관제 vs 느린 관제`, `실시간 관제 vs 사후 관제`라는 두 관제 체계로 설명하지 않는다. 현재 As-built의 DVWA 저지연 Push와 5-Source 후행 조사는 **하나의 Incident 흐름 안에서 역할이 다른 과도기 경로**다.

## 현재 시나리오

```text
DVWA 저지연 Push
→ Wazuh Rule 100103
→ IMDS 대상 명령 실행 성공
→ Incident: SUSPECTED

좁고 강한 Containment
├─ DVWA Workload Quarantine
└─ validation/* Lab 범위의 추가 접근 제한

5-Source 후행 조사
├─ WAF / CloudFront / ALB / DVWA
└─ CloudTrail S3 Data Event

판정
├─ 상관 가능한 GetObject 성공 Evidence → CONFIRMED
├─ 정상 Coverage와 명시적 실패 Evidence → REJECTED / NOT CONFIRMED
└─ 로그 부재·Coverage 불확실 → INCONCLUSIVE
```

Containment는 Workload/Network, Resource/Permission, Credential/Session의 세 축으로 나누어 본다. 상세 기준은 최신 판정 노트를 따른다.

## 확인된 DVWA→Wazuh 하위 경로 측정

2026-08-17 무해 검증 3건은 다음 경로의 Runtime 측정이다.

```text
DVWA
→ CloudWatch Logs
→ Lambda
→ SQS
→ Local Bridge
→ Wazuh localfile(JSONL)
→ Rule 100102 Alert
```

측정값은 `6.439초`, `3.427초`, `3.761초`, 누락 0건이다. 이것은 **DVWA→Wazuh 하위 경로 E2E**이며 Shuffle까지 포함한 전체 프로젝트 E2E는 아니다. 근거: [[20_팀 프로젝트/3차 프로젝트/일일 로그/RAW/2026-08-17_RAW]].
