# 8.19 멘토님과 상담 — 감사 정본

> [!IMPORTANT] 정본의 정의
> 이 문서에서 말하는 감사 정본은 새로 요약한 문서 한 개가 아니다.  
> 다음 두 요소의 합성 결과가 유일한 감사 정본이다.
>
> ```text
> 불변 원본 Git Blob
> fe07af807de8d4e2416c0f7b3c37db67014df4bb
> +
> 승인 교정 원장 C01~C16
> =
> 감사 가능한 최신 정본
> ```

## 왜 이런 구조를 쓰는가

자연어를 자유롭게 요약·재서술한 뒤 `원문과 의미가 100% 동일하다`고 수학적으로 증명할 수는 없다. 대신 보장 대상을 다음처럼 바꾼다.

```text
원문
→ 바이트 단위로 불변 보존

수정
→ 승인된 C01~C16으로만 명시

새 설명
→ NEW / SYNTHESIS로 분리

읽기용 문서
→ 파생 View이며 원본 대체 정본이 아님
```

이 구조에서는 읽기용 문서에 요약 오류가 생겨도 원본과 교정 원장이 손상되지 않는다. 중요한 판단은 언제든 불변 원본과 교정 ID까지 역추적할 수 있다.

## 승인 교정

승인된 변경은 `[[audit/8.19 멘토 노트 - 승인 교정 원장 C01-C16]]`에만 기록한다.

- 교정 ID는 `C01`부터 `C16`까지 정확히 한 번씩 존재해야 한다.
- 각 교정은 문제, 승인된 변경, 적용 대상, 검증 Anchor, 근거를 가진다.
- 교정 ID가 없는 수정은 감사 정본의 일부로 인정하지 않는다.
- 이후 교정이 필요하면 기존 ID를 덮어쓰지 않고 `C17`부터 추가한다.

다음 네 문서는 학습·보고·발표를 위해 재구성한 읽기용 View다.

- `[[8.19 멘토님과 상담 - 최신 판정]]`

- `[[AWS 보안 Telemetry Route 비교]]`
- `[[멘토 상담 후 보고서·발표 반영]]`

이 문서들은 다음 분류를 포함할 수 있다.

| 분류 | 의미 | 정본성 |
|---|---|---|
| `VERBATIM` | 원문을 그대로 재사용 | 원문 Blob으로 검증 가능 |
| `PATCHED` | 승인 교정 ID가 적용된 내용 | 교정 원장으로 검증 가능 |
| `NEW` | 원문 이후 공식 검증으로 새로 추가 | 원문과 동일하다고 주장하지 않음 |
| `SYNTHESIS` | 여러 근거를 읽기 쉽게 재구성 | 편의 View, 독립 정본 아님 |
| `SUPERSEDED` | 당시 기록으로만 보존 | 최신 판단에 사용하지 않음 |

파생 View의 문장이 불변 원본 또는 승인 교정 원장과 충돌하면 다음 우선순위를 적용한다.

```text
1. 불변 원본의 실제 기록
2. 승인 교정 원장 C01~C16
3. 공식 자료와 Runtime Evidence
4. 파생 View의 SYNTHESIS 문장
```

## 기계 검증

다음 파일이 감사 계약을 구성한다.

- `[[audit/8.19 멘토 노트 - 승인 교정 원장 C01-C16]]`
- `audit/8.19-mentor-note-provenance.json`
- `audit/Test-MentorNoteProvenance.ps1`

검증 Script는 다음을 확인한다.

```text
1. 기준 Commit의 Source Blob SHA가 고정값과 같은가
2. 현재 SUPERSEDED 보존본 Blob SHA가 Source와 같은가
3. 파생 View의 현재 Blob SHA가 Manifest에 고정됐는가
4. C01~C16이 누락·중복 없이 존재하는가
5. 각 교정의 필수 Anchor가 대상 문서에 존재하는가
6. 원본 Markdown Block Manifest를 생성할 수 있는가
7. 검증되지 않은 Drift가 발생했는가
```

파생 View를 의도적으로 수정하면 해당 파일의 Blob SHA가 바뀌어 검증이 실패한다. 이후에는 수정 이유와 새 교정 ID 또는 `NEW/SYNTHESIS` 분류를 Manifest에 반영해야 다시 PASS가 된다.

## 보장 범위

| 항목 | 판정 |
|---|---|
| 원문 유실·문자 변형 없음 | **완전 보장 — 동일 Git Blob SHA** |
| 승인된 교정의 목록과 적용 지점 추적 | **보장 — C01~C16 + Anchor** |
| 이후 파생 문서의 무단 Drift 탐지 | **보장 — Blob Pinning** |
| 원문 Block별 SHA Manifest 생성 | **Script로 재현 가능** |
| 자유 재서술 문장의 절대적 의미 동일성 | **보장하지 않음** |
| 파생 View가 원본 전체를 대체함 | **아님** |

즉 다음 문장은 근거와 함께 사용할 수 있다.

> **원본은 바이트 단위로 보존됐고, 최신 판단은 승인된 C01~C16 교정 원장으로만 갱신한다. 네 개의 재구성 문서는 파생 View이며, 정본과 충돌하면 불변 원본과 교정 원장이 우선한다.**
