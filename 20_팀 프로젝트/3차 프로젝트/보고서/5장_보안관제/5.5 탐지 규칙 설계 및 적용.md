# 5.5 탐지 규칙 설계 및 적용

> **전달 경로의 건전성, IMDS Credential endpoint 접근, 보호 S3 Object의 실제 바이트 반환을 서로 다른 Rule로 분리해 각 Alert가 증명하는 범위를 명확히 하였다.**

## 탐지 Rule 구성

| Rule | 역할 | 입력 Source | 증명하는 사실 |
|---|---|---|---|
| `100102` | 저지연 전달 경로 건전성 확인 | DVWA 안전 검증 Event | 지정한 Validation Event가 Push 경로를 거쳐 Wazuh까지 도착함 |
| `100110` | IMDS Credential endpoint 출력 반환 탐지 | DVWA 서버 Audit Event | Credential endpoint 대상 명령에서 출력이 반환됨 |
| `100111` | S3 Object 바이트 반환 탐지 | CloudTrail S3 Data Event | 보호 Object의 `GetObject`가 성공하고 실제 바이트가 반환됨 |

Rule `100102`는 공격 탐지 Rule이 아니다. 안전한 Validation Event를 사용해 CloudWatch Logs → Lambda → SQS → Local Bridge → Wazuh 전달 경로가 동작하는지 확인하는 운영용 건전성 Rule이다.

## Rule 100110 — IMDS Credential endpoint 출력 반환

Rule `100110`의 입력은 DVWA 서버가 Command 실행 결과를 검사해 생성한 Audit Event다.

| 필드 | 조건 | 의미 |
|---|---|---|
| `transport` | `push` | DVWA 저지연 전달 경로로 수집됨 |
| `source` | `dvwa` | DVWA 서버 Audit Event |
| `payload.event_type` | `command.execution` | Command 실행 Event |
| `payload.result` | `succeeded` | Command 실행 처리 성공 |
| `payload.route` | `/vulnerabilities/exec/` | Command Injection 실습 경로 |
| `payload.context.resource` | `ec2_imds` | 대상이 EC2 IMDS임 |
| `payload.context.security_level` | `low` | 취약한 DVWA 보안 수준에서 발생함 |
| `payload.context.stage` | `imds_credential_fetch` | 특정 Role의 Credential endpoint 조회 |
| `payload.context.status` | `output_returned` | 대상 명령에서 출력이 반환됨 |

`imds_role_discovery`는 Role 이름을 확인한 단계이므로 조건에 포함하지 않는다. 특정 Role의 Credential endpoint를 조회한 `imds_credential_fetch` 단계에서 출력까지 반환되어야 발생한다.

> AWS-SOC: DVWA command returned output from the EC2 IMDS credential endpoint.

이 Rule은 Credential 원문이 외부로 탈취됐거나 S3 접근이 완료됐다는 사실까지 증명하지 않는다. 실제 시연에서는 공격 스크립트가 끝난 뒤 Count가 증가했으므로, 공격 완료 전 선제 차단이 아니라 Rule `100111`보다 먼저 관제에 도착하는 저지연 경보로 해석한다.

## Rule 100111 — 보호 S3 Object 바이트 반환

Rule `100111`은 CloudTrail S3 Data Event에서 다음 조건을 모두 만족할 때 발생한다.

| 구분 | 조건 |
|---|---|
| Event Source | `s3.amazonaws.com` |
| Event Name | `GetObject` |
| Event Category | `Data` |
| Account·Region | 승인된 실습 Account와 `ap-northeast-2` |
| 호출 주체 | `aws-topology-primary-karpenter-node` Assumed Role |
| 대상 | 고정 Bucket 패턴과 `validation/capital-one-demo.csv` |
| 응답 | `httpStatusCode=200` |
| 데이터 반환 | `bytesTransferredOut>0` |
| Event 식별자 | CloudTrail UUID 형식의 `eventID` |

> CAPITAL-ONE: Protected S3 object bytes were returned through the compromised node role.

이 Rule은 단순 접근 시도나 `AccessDenied`가 아니라 보호 S3 Object의 실제 바이트 반환을 탐지한다. 다만 Rule `100110`과 같은 사건인지 자동으로 판정하지는 않는다.

## Rule을 분리한 이유

| 구분 | Rule 100110 | Rule 100111 |
|---|---|---|
| 공격 단계 | IMDS Credential endpoint 조회 | 보호 S3 Object 조회 |
| 증거 출처 | DVWA 서버 Audit Event | CloudTrail S3 Data Event |
| 수집 특성 | 저지연 전달 | 5분 주기 수집 |
| 탐지 의미 | Credential endpoint 대상 명령의 출력 반환 | 보호 Object의 실제 바이트 반환 |
| 판단 범위 | AWS 권한 악용을 단독 확정하지 않음 | 앞선 DVWA Event와의 인과관계를 단독 확정하지 않음 |

두 Rule은 서로 다른 계층의 독립 증거다. 하나의 Rule로 합치면 IMDS 접근과 실제 S3 데이터 반환이라는 서로 다른 보안 사실과 수집 지연을 구분하기 어렵다. 관제자는 Timeline에서 Event 시각, `take_id`, Pod 정보, IAM Role 및 S3 Object를 비교해 동일 사건인지 조사한다.

## Rule 검증

| Rule | Positive | Negative | 확인 결과 |
|---|---:|---:|---|
| `100110` | 1건 | 8건 | 허용된 IMDS Credential fetch와 출력 반환 조건에서만 발생 |
| `100111` | 1건 | 15건 | Account·Region·Role·Bucket·Object·성공 조건이 일치할 때만 발생 |

Static Rule Test는 조건 분기를 검증하며 실제 수집과 Runtime 대응을 대신하지 않는다. 최종 보고서에서는 Rule Test 결과와 Wazuh Runtime Alert를 구분해 제시한다.
