# 보안관제 구현 결과 및 핵심 성과

> **여러 AWS·EKS 로그에서 공격의 서로 다른 단계를 탐지하고, 검증된 경보만 실제 격리와 취약점 완화로 연결하는 추적·복구 가능한 보안관제 체계를 구현하였다.**

| 핵심 성과 | 구현 결과 |
|---|---|
| **단계별 탐지** | Rule `100110`으로 IMDS Credential endpoint 대상 명령의 출력 반환을, Rule `100111`로 보호 S3 Object의 실제 바이트 반환을 구분해 탐지하였다. |
| **안전한 자동 대응** | Alert의 Rule·Schema·해시·대상을 검증한 뒤 침해 Pod 격리·보존과 DVWA `low → impossible` 전환을 사전 승인된 Workflow로만 실행하였다. |
| **추적과 복구** | 자동 대응을 GitHub Actions Run·Git Commit·Argo CD Revision으로 추적하고 Reset Workflow로 촬영·재검증 기준선까지 복구하였다. |

Rule `100110`은 공격 스크립트 완료 전 차단을 보장하는 Rule이 아니라, 5분 주기의 Rule `100111`보다 먼저 관제와 대응을 시작하게 하는 저지연 경보다.

> **자동 대응 범위:** `low → impossible`은 소스코드를 자동으로 작성·수정한 조치가 아니다. 안전하고 재현 가능한 대응 경로를 검증하기 위해 DVWA에 사전 구현된 방어 프로필을 고정·가역 Playbook으로 배포한 것이며, 실제 운영환경에서는 Patch 배포와 탈취 자격증명 폐기가 추가로 필요하다.
