# Wazuh 설치

## 설치 목표

프로젝트의 AWS 로그를 한곳에서 검색·분석하고 탐지 규칙을 적용하기 위해, 로컬 Docker 환경에 Wazuh 중앙 구성요소를 설치한다.

이번 단계에서는 고가용성 구성이 아닌 **Single-node stack**을 사용한다. 한 대의 Docker 호스트에서 다음 세 구성요소를 각각의 컨테이너로 실행하는 방식이다.

- **Wazuh Manager**: 수집된 이벤트를 분석하고 탐지 규칙을 적용한다.
- **Wazuh Indexer**: 이벤트와 Alert를 저장하고 검색할 수 있게 색인한다.
- **Wazuh Dashboard**: 검색·분석·시각화를 제공하는 웹 화면이다.

AWS 로그 연결과 Shuffle SOAR 연동은 Wazuh 자체의 기동과 데이터 보존을 먼저 확인한 뒤 진행한다.

## 2. 공식 Docker 구성 다운로드

```bash
git clone https://github.com/wazuh/wazuh-docker.git -b v4.14.7
```

- 설치 위치: `D:\Wazuh\wazuh-docker`
- 고정 버전: `v4.14.7`
- 확인된 체크아웃 커밋: `adcc5b5`

버전 태그를 직접 체크아웃했기 때문에 나타나는 `detached HEAD`는 정상이다. 애플리케이션 소스를 개발하려는 것이 아니라 동일한 Wazuh 구성을 재현하기 위해 특정 버전에 고정한 상태다.

출력 중 `refs/tags/v4.14.7 ... is not a commit` 경고가 있었지만, Git이 태그를 실제 릴리스 커밋 `adcc5b5`로 해석하여 체크아웃을 완료했으므로 clone 실패는 아니다.

## 3. 내부 통신용 인증서 생성

`single-node` 디렉터리에서 다음 명령을 실행했다.

```bash
cd wazuh-docker/single-node
docker compose -f generate-indexer-certs.yml run --rm generator
```

명령의 의미는 다음과 같다.

- `-f generate-indexer-certs.yml`: 기본 Compose 파일 대신 인증서 생성 전용 설정을 사용한다.
- `run generator`: 인증서 생성 서비스를 일회성으로 실행한다.
- `--rm`: 작업이 끝난 임시 컨테이너만 삭제한다. 호스트 폴더에 생성된 인증서는 남는다.

![[Pasted image 20260812171713.png]]

생성기는 Manager·Indexer·Dashboard 및 Filebeat가 서로 TLS로 통신할 때 사용할 인증서를 만들었다.

![[Pasted image 20260812171726.png]]

### 실행 결과 판정

출력에 `/wazuh-certs-tool.sh: line 636: find: command not found`가 표시됐다. 다만 2026-08-12 확인 결과, 다음 경로에 인증서와 키 12개가 실제로 생성돼 있었다.

```text
D:\Wazuh\wazuh-docker\single-node\config\wazuh_indexer_ssl_certs\
```

따라서 **인증서 생성 결과물은 존재한다.** 다만 `find` 경고가 권한 조정 단계에서 발생했으므로, 최종 성공 여부는 Wazuh 컨테이너들이 이 인증서를 실제로 읽고 정상 기동하는지 확인한 뒤 확정한다.
