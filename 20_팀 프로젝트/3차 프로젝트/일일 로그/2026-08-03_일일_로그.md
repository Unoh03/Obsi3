# 2026-08-03 프로젝트 일일 로그

## 결정

| 결정 | 이유 | 영향 |
|---|---|---|
| 비용 최적화는 Runtime Down 상태에서 Plan 검토 | 실행 중 Resource를 건드리지 않기 위함 | 현재 Runtime 변경과 최적화 Source 변경을 분리 |
| Valkey는 주석 삭제보다 `enable_valkey` 선택화 우선 | 재사용 가능성과 Terraform State 일관성 보존 | 실제 BANK DVWA 사용 여부 확인 후 비활성 후보 |
| Cross-Region DR 유지 | DR 조치 전후와 로그 증거가 필요 | 지역별 NAT 등 DR 비용은 당장 유지 |
| Primary Multi-AZ는 DR과 별도 판단 | 서울 내부 AZ 장애조치와 Cross-Region DR의 역할이 다름 | 시나리오 필요성에 따라 Single-AZ 후보 검토 |

## 막힌 점

| 문제 | 확인한 사실 | 다음 확인 |
|---|---|---|
| SQLi WAF Match 없음 | 같은 시간창에서 SQLi는 Application에 도달했으나 WAF Event는 확인되지 않음 | SQLi Managed Rule 적용·Override·Logging Filter 확인 |
| XSS 탐지 후 허용 | WAF가 XSS를 Match했지만 관찰용 `COUNT`로 최종 `ALLOW` | 조치 전후 실험에서 차단 전환 여부 결정 |
| Application 로그의 증명 한계 | 요청과 HTTP 상태는 보이지만 DB 반환 데이터·Browser Script 실행은 기록되지 않음 | Screenshot·응답 Sanitization·Application Audit Event를 함께 수집 |
| WEB-01 Rate 차단 미검증 | 약 60초 실행에서 COUNT 2·BLOCK 0 | 더 긴 bounded 실행 필요 여부를 팀 시나리오와 함께 결정 |

## 보안·비용·운영 주의

- Access Log Query String에 공격 Payload가 남으므로 실제 개인정보·Credential이 URL에 포함되지 않도록 해야 한다.
- Application Log의 Source IP는 내부 전달 주소이고 실제 Client IP는 WAF 등 Edge 로그에서 확인해야 한다.
- SQLi·XSS가 Application까지 도달했다는 사실과 실제 취약점 악용 성공은 별도 증거로 판정한다.
