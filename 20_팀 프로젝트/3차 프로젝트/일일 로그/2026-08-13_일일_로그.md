## 결정

| 결정 | 이유 | 영향 |
|---|---|---|
| SIEM 검증 기준을 동일 `eventID`의 Raw Event와 Alert 연결로 둔다 | 단순 로그 수집량과 실제 탐지를 구분하기 위해 | 공격부터 판정까지 한 사건으로 설명 가능 |
| Rule에 `amazon` Group을 추가한다 | AWS 전용 화면의 고정 Group Filter가 Custom Alert를 숨겼기 때문 | 다음 Alert부터 AWS 화면 노출 검증 가능 |
| 초보자용 Saved View·Dashboard를 만든다 | Field 이름과 검색 문법을 모르면 기본 UI 사용이 어려움 | 검색 없이 사건·위험도·다음 조치를 확인하는 방향 확정 |
| 오늘은 같은 공격을 다시 실행하지 않는다 | 기존 Alert에는 Group 변경이 소급되지 않으며 재실행 실익이 작음 | 다음 시연 TAKE에서 화면 노출을 함께 검증 |

## 막힌 점

| 문제 | 확인한 사실 | 다음 확인 |
|---|---|---|
| AWS 전용 Events 화면에서 Rule `100100`이 보이지 않음 | Alert 부재가 아니라 `rule.groups: amazon`과 Custom Rule Group의 불일치 | 새 Alert에서 AWS 화면 노출 확인 |
| 검색 과정이 초보자에게 어려움 | `TakeId`는 CloudTrail에 없고 Field Filter를 직접 알아야 함 | Capital One 전용 Saved View·Dashboard 제작 |

## 보안·비용·운영 주의

- 실습에는 고정된 가짜 데이터만 사용했고, 획득한 임시 Credential 값은 출력·저장하지 않았다.
- 전체 Alert JSON과 화면에는 Account, Bucket, IP, 임시 Access Key ID 등이 포함될 수 있으므로 외부 보고서에는 필요한 Field만 선별한다.
- Custom Rule은 Docker Named Volume에 있으므로 `docker compose down -v`를 실행하면 사라질 수 있다. 최종 재현 가능한 Host 원본이 필요하다.
- AWS Daily Runtime은 별도 종료 확인이 필요하다. 이번 문서 정리 과정에서는 `daily-down`을 실행하지 않았다.
