# 입사지원서 준비 현황과 3차 프로젝트 정리

## 이 노트의 역할

이 노트는 자소서 문장을 바로 수정하기 전에 현재 입사지원서의 상태와 3차 프로젝트에서 실제로 구축한 내용을 정리하는 준비 문서다.

- 자소서 문장을 새로 쓰거나 고치지 않는다.
- 빨간색 문장은 취업 코치의 코멘트, 파란색 문장은 코치가 제시한 예시로 구분한다.
- 현재 지원서는 회사별 지원동기까지 반영하기 전의 공통 마스터본이다.
- 3차 프로젝트 구축 전반은 장운호가 AI를 보조 도구로 사용해 직접 수행했다는 사용자 확인을 기준으로 한다.
- 구현 파일, Git 기록, Runtime 증거, 보고서의 주장을 구분하고 최종 문장에는 확인된 범위만 사용한다.

## 프로젝트 전체 흐름

```text
AWS·EKS의 애플리케이션과 보안 로그
→ 정기 수집 경로와 DVWA 저지연 전달 경로
→ Wazuh Decoder·Rule 분석과 단계별 Alert
→ Shuffle의 Rule·Schema·Hash·대상 검증
→ 고정된 GitHub Actions Workflow 실행
→ Argo CD가 Git 변경을 EKS에 동기화
→ 침해 Pod 격리·보존 또는 DVWA 방어 수준 전환
→ Run·Commit·Argo Revision·Pod 상태를 증적으로 남기고 Reset
```

## 문제 해결 흐름 후보

### 1. 비용과 재현성

- 문제: 전체 환경을 매일 삭제하면 ECR Image, OIDC·IAM 연결, GitOps 구성, 보안 로그처럼 보존해야 할 항목도 함께 사라짐.
- 대응: Foundation과 Daily Runtime의 Root·State·수명주기를 분리함.
- 확인할 결과: Daily Down 뒤 Runtime은 제거되고 Foundation은 유지되는 실행 근거.

### 2. Terraform State 밖의 Karpenter 자원

- 문제: Karpenter가 만든 NodeClaim·EC2가 남아 네트워크 자원 삭제를 방해함.
- 대응: Terraform Destroy 전에 Karpenter 자원을 정리하고 Tag가 일치하는 EC2 종료를 확인하도록 절차를 보완함.
- 확인할 결과: 잔여 Runtime 0, Foundation 보호, 진단 로그와 정적 테스트.

### 3. 10분 Poll의 탐지 지연

- 문제: DVWA 위험 Event가 다음 Poll까지 대기해 관제 시연과 초기 대응이 늦어짐.
- 대응: 기존 Poll·Archive는 유지하고 DVWA에만 CloudWatch Logs Subscription 기반 저지연 Route를 추가함.
- 확인한 결과: 안전한 Validation Event N=3에서 Event→Wazuh Alert 3.427~6.439초, 누락 0건.
- 한계: 장기 부하, 장애 Window, Shuffle 이후 E 구간까지 증명하는 수치는 아님.

### 4. 탐지와 침해 확정의 구분

- 문제: 한 Alert만으로 공격 전체 성공이나 넓은 대응을 확정하면 오판 위험이 있음.
- 대응: Rule `100110`과 `100111`을 서로 다른 단계의 증거로 구분하고 각 Rule이 증명하지 못하는 범위를 명시함.
- 확인할 결과: Source Event ID, Alert ID, 정상 대조군을 같은 TAKE로 연결.

### 5. 자동 대응의 오조치 범위

- 문제: Alert의 임의 값을 그대로 실행하면 다른 Namespace·Workload까지 영향을 줄 수 있음.
- 대응: Rule·Schema·Hash·신선도·Account·Region·Repository·Workflow·Pod UID를 재검증하고 고정된 대응만 허용함.
- 확인할 결과: Shuffle Execution, GitHub Run, Commit, Argo Revision, 실제 Pod 상태와 재공격 결과.

## 현재 확인이 필요한 것

- [ ] 프로젝트 총인원
- [ ] 최종 촬영 TAKE에서 Rule `100110` → Shuffle → GitHub Run → Argo → Pod 격리 식별자 연결
- [ ] 최종 촬영 TAKE에서 Rule `100111` → Shuffle → GitHub Run → Commit → Argo → `impossible` 식별자 연결
- [ ] Capital One 공격과 정상 사용자 대조 실험이 같은 조건·Object·탐지 기준으로 비교됐는지 확인
- [ ] 활용 가능 기술을 `직접 구축`, `프로젝트에서 사용`, `교육 실습`, `학습`으로 분류
- [ ] 프로젝트 페이지에 사용할 아키텍처 그림 1~3개 선택
- [ ] 코치의 빨간 코멘트 중 채택할 요구와 파란 예시 중 사용할 문장 결정
