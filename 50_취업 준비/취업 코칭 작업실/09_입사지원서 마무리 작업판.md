# 입사지원서 마무리 작업판

## 목적

[[50_취업 준비/입사지원서_장운호.docx|입사지원서_장운호.docx]]를 제출 가능한 기준본으로 만들기 전에 문서의 예시·메모·빈칸을 분리하고, 자기소개서와 프로젝트 주장을 실제 근거에 연결한다.

이 작업판은 글을 대신 쓰는 초안이 아니라, 어떤 문장을 유지·수정·삭제할지 결정하기 위한 기준이다.

## 기준 문서

| 항목 | 현재 상태 |
|---|---|
| 기준본 | `50_취업 준비/입사지원서_장운호.docx` |
| 확인일 | 2026-09-04 |
| 문서 구성 | 9페이지, 인적사항·교육/기술·자기소개서 4문항·프로젝트 양식 |
| 편집 상태 | 내용 초안. 템플릿 예시, 작성 메모, 빈 프로젝트 페이지가 남아 있어 제출본 아님 |
| 보존 원칙 | 최초 수정 전에 별도 작업본을 만들고 이 기준본은 비교용으로 보존 |

## 페이지별 정리 대상

| 페이지 | 현재 내용 | 마무리 전 필요한 작업 |
|---|---|---|
| 1 | 인적사항, GitHub, 병역, 자격증, 학력 | 예시 병역 항목과 실제 병역 항목의 중복 제거, 개인정보·링크·자격증 사실 재확인 |
| 2 | 교육 수료와 활용 가능 기술 | 실제 사용·설명 가능한 기술만 남기고 단순 나열을 역할·프로젝트 근거와 대조 |
| 3 | 강·장점, 관심 분야 문항 | 빨간 작성 메모와 파란 대체 문장 제거, Capital One 대조 실험과 탐지 결과의 Runtime 근거·개인 기여 재확인 |
| 4 | 습득 기술·문제 해결, 지원동기·포부 | 빨간 작성 메모와 파란 추가 문장 제거, Terraform 수명주기·Karpenter 복구의 직접 수행 범위 확정 |
| 5 | 프로젝트 예시 양식 | 지하철 웹 서비스, ECS Fargate 등 타 프로젝트 예시와 날짜·인원·목표 빈칸을 전부 제거하고 실제 프로젝트로 교체 |
| 6 | 프로젝트 참여소감 양식의 나머지 | 5페이지와 합쳐 실제 프로젝트 한 건으로 완성하거나 불필요하면 페이지 자체를 제거 |
| 7~9 | 인프라 아키텍처 설계 빈 양식 | 실제 최종 프로젝트의 검증된 아키텍처·구성 설명으로 채울지, 지원서에서 제외할지 결정 |

## 문서 전체 형식 확인

- 보라색 헤더, 표, 구분선, 로고의 기본 디자인은 유지한다.
- Word 렌더링에서 섹션 제목 앞 특수기호가 빈 사각형으로 나타났다. 편집할 때 일반 글머리표로 교체하거나 사용 글꼴을 확인한다.
- 6~9페이지는 내용이 거의 없어 현재 상태로 제출하면 미완성 양식으로 보인다.
- 자소서 문장은 페이지를 넘기지 않았지만, 회사별 글자 수가 정해지면 내용과 여백을 다시 맞춘다.

## 현재 자기소개서 문항과 대표 소재

| 문항 | 현재 소재 | 현재 판정 |
|---|---|---|
| 강·장점 | Capital One 기반 공격과 정상 대조 실험, 탐지 조건 검증 | 강한 최신 사례 후보. 실제 Alert·대조군·개인 수행 범위를 증거로 다시 닫아야 함 |
| 관심 분야와 적용 경험 | Injection 원인·조치 분석에서 IAM·IMDS·워크로드 권한으로 확장 | 방향은 자연스럽지만 웹에서 클라우드로 넘어가는 연결을 한 문단으로 정리해야 함 |
| 습득 기술과 문제 해결 | Foundation/Daily Runtime 분리, Karpenter 잔여 자원 복구 | 구체적이고 직무 연결성이 높음. 팀 Terraform과 개인 보정·검증 범위를 분리해야 함 |
| 지원동기와 포부 | 공격 원인 분석, 조치 설계, 재검증까지 연결하는 보안 엔지니어 | 공통본으로 사용 가능. 실제 지원 회사와 직무가 정해지면 회사 요구와 연결 필요 |

## 사실과 출처 경계

- [[50_취업 준비/8월 20일 취업 코칭 상담|8월 20일 상담]]은 취업 코치의 채용·직무 조언이다.
- [[20_팀 프로젝트/3차 프로젝트/8.19 멘토님과 상담|8.19 상담]]은 3차 프로젝트 기술 멘토의 Telemetry·관제·대응 피드백이다.
- 기술 멘토 상담은 관심의 발전과 설계 판단을 설명하는 보조 근거이며, 구현·Runtime 성공의 직접 증거가 아니다.
- 3차 프로젝트 팀 결과는 [[20_팀 프로젝트/3차 프로젝트/보고서/5장_보안관제/핵심 결과 요약|보안관제 핵심 결과 요약]]에서 찾되, 개인 기여는 별도로 확인한다.
- 탐지·대응 주장은 [[20_팀 프로젝트/3차 프로젝트/시연 장면별 근거 파일|시연 장면별 근거 파일]]의 `Runtime 증거`와 `공백·잠금` 구분을 우선한다.

## 작성 전 게이트

- [ ] 3차 프로젝트의 최종 팀 결과와 장운호 개인 기여를 분리한다.
- [ ] 강·장점 문항의 공격·정상 대조 실험과 Rule 탐지 결과를 같은 TAKE 근거로 확인한다.
- [ ] Terraform 수명주기와 Karpenter 복구에서 직접 실행·판단·수정한 범위를 확정한다.
- [ ] 교육 수료사항과 기술 목록을 현재 사실로 갱신한다.
- [ ] 프로젝트 페이지에 넣을 프로젝트 수와 우선순위를 정한다.
- [ ] 지원 직무·회사·공고·문항별 글자 수를 정한다.
- [ ] 공통 마스터본을 완성한 뒤 회사별 사본에서 지원동기와 요구 역량을 조정한다.
- [ ] 편집 후 DOCX 전체 페이지를 다시 렌더링해 글자 깨짐, 표 밀림, 빈 페이지를 확인한다.
